# Can LLMs Generate Correct, Secure, and Efficient Code Simultaneously?

This repository contains the implementation and experimental pipeline for jointly evaluating the **correctness**, **security**, and **execution efficiency** of code generated by large language models (LLMs).

We extend **CWEval** with runtime-based efficiency evaluation to construct **CWEval-Effi**, and evaluate generated programs across five programming languages:

- C
- C++
- Go
- Python
- JavaScript

The repository also contains implementations for different generation strategies and quality-improvement methods, including quality-oriented prompting, repair, and supervised fine-tuning (SFT).

---

## Overview

Traditional code-generation benchmarks mainly focus on functional correctness. We evaluate generated code from three complementary dimensions:

- **Correctness (C):** whether the generated program passes the functional tests.
- **Security (S):** whether the generated program satisfies the security requirements defined by CWEval.
- **Efficiency (E):** whether the generated program achieves competitive execution efficiency compared with the benchmark reference implementation.

We additionally report their intersections and conditional efficiency metrics, including **CS** and **CSE**, to measure whether generated programs satisfy multiple quality requirements simultaneously.

## Code Generation

## Quality-Oriented Prompting

TrustCoder evaluates four prompting strategies:

- **Base**
- **Security**
- **Efficiency**
- **CSE**

Greedy generation is implemented in:

```bash
python cweval/generatewithprompt.py [arguments]
```

Sampling-based generation is implemented in:

```bash
python cweval/generatewithprompt_sampling.py [arguments]
```

In our sampling experiments, multiple candidate programs are generated for each benchmark task to study the robustness of different prompting strategies.

## Evaluation

### Correctness and Security

Generated programs can be evaluated using:

```bash
python cweval/evaluate.py [arguments]
```

The evaluation follows the functional and security testing procedure of CWEval.

---

### Efficiency Evaluation

Runtime efficiency is evaluated relative to the reference implementation.

For greedy generation:

```bash
python cweval/evaluatewitheffi.py [arguments]
```

For sampling experiments:

```bash
python cweval/evaluatewitheffi_sampling.py [arguments]
```

The efficiency evaluator performs warm-up executions followed by repeated runtime measurements to reduce measurement noise.

---

## Evaluation Metrics

We report the following metrics.

| Metric | Description |
|---|---|
| **C** | Functional correctness rate |
| **S** | Security success rate |
| **CS** | Rate of programs satisfying both correctness and security |
| **ER_F** | Efficiency success rate among functionally correct programs |
| **ER_FS** | Efficiency success rate among functionally correct and secure programs |
| **AS_F** | Average speedup among functionally correct programs |
| **AS_FS** | Average speedup among functionally correct and secure programs |
| **CSE** | Rate of programs satisfying correctness, security, and efficiency simultaneously |

The joint **CSE** metric is used to characterize whether a generated program simultaneously satisfies all three quality requirements.

## Repair

We provide two repair strategies.

### Feedback-Guided Repair

```bash
python cweval/repair.py [arguments]
```

The repair model receives evaluation feedback and attempts to revise candidates that fail one or more quality requirements.

### Repair with Code Context

```bash
python cweval/repair_with_code.py [arguments]
```

This variant additionally provides code context to the repair model during revision.

---

## Supervised Fine-Tuning

The SFT implementation is provided in:

```text
cweval/train_cse_sft.py
```

The training corpus combines different types of supervision, including:

- general code-generation examples;
- security-oriented code examples;
- efficiency-oriented code examples.

To start training:

```bash
python cweval/train_cse_sft.py [arguments]
```

The current implementation supports parameter-efficient fine-tuning with LoRA.

## Benchmark: CWEval-Effi

We extend CWEval with runtime-based efficiency evaluation and refer to the resulting evaluation setting as **CWEval-Effi**.

CWEval-Effi retains the original:

- programming specifications;
- functional tests;
- security requirements;

and additionally introduces runtime comparison against the corresponding reference implementation.

This enables generated programs to be evaluated jointly in terms of:

```text
Correctness × Security × Efficiency
```

rather than treating the three dimensions independently.

## Experimental Pipeline

The overall experimental workflow is:

```text
CWEval-Effi
     │
     ▼
Prompt Construction
     │
     ▼
LLM Code Generation
     │
     ├── Base Prompt
     ├── Security Prompt
     ├── Efficiency Prompt
     └── CSE Prompt
     │
     ▼
Generated Programs
     │
     ├── Repair
     └── SFT
     │
     ▼
Evaluation
     │
     ├── Correctness
     ├── Security
     └── Efficiency
     │
     ▼
Joint CSE Analysis
```
